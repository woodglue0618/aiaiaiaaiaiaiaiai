아래는 초기 설계이며, 위 구현 현황과 다른 부분은 후속 확장 계획입니다.

## 목표
현재 위치에서 목적지를 정하고, 텍스트 박스에 이동 상태를 적으면 실제 지도 위에서 조건에 맞는 보행 경로를 추천한다. 기존 서울 정동 고정 시나리오는 독립적인 예시 모드로 유지한다.

## 사용자 흐름
1. '현재 위치 사용'을 눌러 위치 권한을 허용한다.
2. 지도에 현재 위치와 정확도 범위를 표시하고 사용자가 출발 핀을 수정할 수 있게 한다.
3. 목적지를 검색하거나 지도에서 선택한다.
4. 텍스트 박스에 상태를 입력한다. 예: '무릎이 아파서 계단과 오르막을 피하고 중간에 쉬고 싶어요.'
5. 분석된 조건을 수정 가능한 칩으로 표시한다. 계단 회피 / 경사 최소화 / 휴식 우선.
6. 실제 경로 후보를 비교하고 조건에 맞는 경로와 선택 근거를 보여준다.
7. 현 위치 이동에 따라 남은 거리와 다음 구간을 표시한다.

## 기술 구성
- 프런트엔드: 기존 웹 화면에 실제 지도, 위치 정확도, 목적지 검색, 상태 입력창을 추가.
- 위치: 브라우저 Geolocation API. HTTPS 및 사용자 권한 필요. 거부·시간 초과·실내 오차에는 주소 검색/지도 핀으로 대체. 모바일 브라우저에서 현장 검증.
- 지도/검색/보행 경로: TMAP 우선 검토. 키 발급 후 실제 응답의 보행 경로 옵션·대안 경로·구간 속성을 확인한다. API가 제공하지 않는 접근성 속성을 임의로 생성하지 않는다.
- 상태 해석: 서버에서 LLM으로 정해진 구조의 이동 조건을 추출. 진단을 수행하지 않는다. 명시하지 않은 수치 제한은 임의로 확정하지 않는다. 사용자 확인/수정 후 경로에 적용.
- 경로 계산: 지도 API 또는 현장 보행 그래프가 실제 경로를 생성한다. LLM은 도로·시설·경로 좌표를 만들지 않는다.
- 서버: 상태 해석 및 경로 조회 엔드포인트. 비밀 API 키는 서버 환경 변수에 저장. 정확한 위치는 경로 조회에 사용하고 LLM에는 불필요하게 보내지 않는다. 원문 상태와 위치를 기본 영구 저장하지 않는다.

## 상태 해석 예시
| 입력 | 필수 조건 | 선호 조건 |
| --- | --- | --- |
| 휠체어를 타고 있어요 | 계단 구간 제외 | 낮은 경사, 넓은 보도 |
| 무릎이 아파 오르막이 힘들어요 | 사용자가 명시한 이동 불가 조건 | 경사·계단에 높은 회피 가중치 |
| 오래 걷기 힘들고 중간에 쉬고 싶어요 | 명시한 최대 연속 이동 시간 | 짧은 경로, 확인된 휴식 지점 경유 |
| 10분마다 쉬고 싶어요 | 요청한 휴식 간격을 만족하는 확인된 경유지 | 전체 우회 거리 최소화 |

'힘들다/피하고 싶다'와 '이용할 수 없다'를 구분한다. 애매한 조건은 수정 가능한 칩으로 제안한다.

## 경로 적용 원칙
1. 현장 확인된 구간 데이터: 계단, 경사, 보도 폭, 턱, 휴식 지점, 진입로, 확인일.
2. 필수 조건을 위반한 구간은 탐색 그래프에서 제외한다. 후보 평가 방식이라면 해당 후보를 탈락시킨다.
3. 나머지 경로를 거리·경사·계단 부담·연속 이동 거리·미확인 구간 비용으로 비교한다.
4. 휴식 요구가 있으면 확인된 휴식 지점을 실제 경유지로 추가하고 경로를 다시 계산한다.
5. 필수 접근성 속성이 확인되지 않으면 충족으로 간주하지 않는다. '미확인'을 표시하고 조건 충족 경로를 찾지 못했다면 그렇게 안내한다.
6. 단일 경로를 재정렬하는 것만으로 개인화 경로를 구현했다고 처리하지 않는다. 대안이 없으면 검증된 로컬 그래프 또는 지원되는 경유지 기능으로 후보를 만든다.

## 확정된 시연 장소
- 서울대학교사범대학부설중학교: 서울특별시 성북구 월곡로 36.
- 주소 출처: 서울특별시성북강북교육지원청 https://sbgbedu.sen.go.kr/CMS/introduction/introduction04/introduction0401/introduction040104/1207520_6725.html
- 초기 지도는 학교 주변으로 열고, 실제 출발지는 사용자가 허용한 현재 위치로 설정한다. 학교 주소를 현 위치로 가장하지 않는다.
- 위치 오차가 큰 교실에서는 출발지를 학교 교문 쪽 보행로로 직접 보정한다. 교문 좌표와 실제 출입 가능 여부는 구현 시 확인한다.
- 1차 시연은 학교 교문을 기준으로 약 500m 내의 외부 보행로. 필요 시 1km로 확장한다.
- 목적지는 실제 장소 검색 후 주변 장소 2~3곳을 선정한다. 방문 가능한 출입구와 접근성 확인 전에는 확정하지 않는다.
- 교내 동선은 지도 API에 없는 경우가 있으므로, 교내 안내가 필요하면 별도 현장 보행 그래프를 구축한다.

## 학교 현장 시연 시나리오
1. 같은 현재 위치와 목적지를 고정한다.
2. '휠체어라 계단은 이용할 수 없어요' 입력: 확인된 계단 구간을 제외한다.
3. '무릎이 아파 오르막이 힘들어요' 입력: 확인된 낮은 경사의 경로를 우선한다.
4. '오래 걷기 힘들어 중간에 앉아서 쉬고 싶어요' 입력: 확인된 휴식 장소를 경유하도록 계산한다.
5. 대체 경로나 검증 데이터가 없으면 상태별로 다른 길이 존재한다고 꾸미지 않고 한계를 표시한다.

## 현장 시연 범위
- 위치에 기반한 지도/목적지 검색은 지원 지역에서 사용.
- 접근성 맞춤 경로 시연은 실제 시연 장소 주변 약 500m~1km의 검증 구역부터 구현.
- 가까운 목적지 2~3곳, 경로 대안 2개 이상, 서로 다른 계단/경사/휴식 특성을 준비.
- 검증 구역 밖에서는 일반 보행 경로와 접근성 데이터 부족을 명시. 맞춤 조건 충족을 보장하지 않음.
- GPS가 안 잡히면 행사장 출발 핀으로 대체하되 '직접 지정한 출발지'를 표시. 녹화/사전 경로는 별도 예시 모드로만 사용.

## 구현 순서
1. 실제 지도 + 현재 위치 + 목적지 검색 + 실제 보행 경로 연결.
2. 텍스트 상태 입력 + 구조화 해석 + 수정 가능한 조건 칩.
3. 시연 지역 접근성 데이터 + 필수 조건 제외 + 비용 기반 경로 탐색.
4. 경로 비교 + 추천 근거 + 휴식 경유지 + 현 위치 기반 안내.
5. 실제 휴대폰에서 같은 출발/도착으로 상태만 바꿔 경로 변경을 검증.

## 완료 기준
- 실제 시연 위치에서 출발지를 잡거나 직접 보정할 수 있다.
- 같은 출발/도착에서도 입력한 상태에 따라 실제 선택 구간/경유지 또는 추천 결과가 달라진다.
- 휠체어 필수 조건 경로에 확인된 계단이 포함되지 않는다.
- 휴식 지점은 실제 경로에 반영되며 위치를 확인할 수 있다.
- 데이터가 없거나 조건을 만족하는 경로가 없으면 이를 솔직히 표시한다.
- 위치 권한 거부, 목적지 검색 실패, API 오류, 조건 해석 실패를 처리한다.

## 필요한 외부 준비
시연 장소는 서울대학교사범대학부설중학교로 확정. 지도/보행 경로 API 키, 서버 LLM API 연결, 교문 위치 및 주변 경사·계단·휴식 장소의 현장 확인이 필요하다.
